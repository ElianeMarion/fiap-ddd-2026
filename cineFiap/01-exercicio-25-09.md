## 🎯 Objetivo da Atividade

Desenvolver a API de gerenciamento de **Salas de Cinema** adotando o fluxo profissional de trabalho com **Git/GitHub** e o conceito de **fatias verticais** (*Vertical Slices*).

Em vez de construir todas as camadas de uma só vez, você implementará **uma funcionalidade completa de ponta a ponta por vez** (do DAO até o Controller), testará no Postman/Insomnia e **realizará um commit específico para cada etapa**.

Nesta atividade, você deverá evoluir a API de gerenciamento de Salas de Cinema, implementando uma nova camada de Service entre o Controller e o DAO. Até o momento, o Controller realiza diretamente as chamadas ao SalaDAO. Essa abordagem faz com que regras de negócio fiquem concentradas no Controller, dificultando a organização, manutenção e evolução do sistema.
Requisição 
      HTTP 
       ↓
    Controller
       ↓
    Service 
       ↓
      DAO
       ↓
  Banco de Dados


A partir desta atividade, a arquitetura deverá seguir o fluxo:
O fluxo de trabalho será estruturado da seguinte forma:
- 🚀 **ETAPA 0 (Pré-requisito):** Fork, Clone, Criação da Branch e Preparação Git
- 🟢 **ETAPA 1:** Listagem de todas as salas  (`GET /salas`) + **Commit 1**
- 🟡 **ETAPA 2:** Consulta de sala por ID (`GET /salas/{id}`) + **Commit 2**
- 🟡 **ETAPA 3:** Cadastro de nova sala (`POST /salas`) + **Commit 3**
- 🟡 **Etapa 4:** Alteração de uma sala (`PUT /salas/{id}`) + **Commit 4**
- 🔵 **Etapa 5:** Exclusão lógica(`PUT /salas/excluir/{id}`) + **Commit 5**
- 

Para isso, você construirá as seguintes peças da arquitetura:
- **Service**: Camada de negócio
- **Controller**: exposição da API HTTP

## 🟡 ETAPA 2: Consulta de Sala Ativa por ID (`GET /salas/{id}`)

Agora que a listagem funciona, implementaremos a busca pontual de uma sala pelo seu ID.

```text
Postman (GET /salas/1) ➔ SalaController  ➔ Sala Service ➔ SalaDAO ➔ Oracle
                              │                 │
                         (Se achar: 200    (Busca por ID)
                          Se não: 404)    
```

### 2.1 Camada DAO
O método correspondente já está criado na camada `DAO` de sala, adicione.

### 2.2 Camada Service
Na classe Service de sala, implemente o método de busca por ID:

Lógica: Chame o método criado no item 2.1 da classe SalaDAO e verifique se a sala não está excluída logicamente, isso acontecerá se a dataExclusão estiver preenchida.

### 2.2 Camada Controller
Na classe `Controller` de sala, adicione o endpoint de busca por ID:
- **Anotação:** `@GetMapping("/{id}")`
- **Lógica:**
    - Invoque o método criado no item 2.2 de `Service`.
    - Se a sala for encontrada, retorne status **200 OK** com a sala.
    - Se a sala não existir ou estiver excluída, retorne status **404 Not Found**.

### 🧪 Teste Prático da Etapa 2
1. **Cenário de Sucesso (ID existente):**
    - **Método:** `GET`
    - **URL:** `http://localhost:8080/salas/1`
    - **Status esperado:** `200 OK`
    - **Corpo:** Dados da sala em JSON.
2. **Cenário de Recurso Inexistente:**
    - **Método:** `GET`
    - **URL:** `http://localhost:8080/salas/999`
    - **Status esperado:** `404 Not Found` (sem corpo).

## 🔵 ETAPA 3: Inserção de Dados / Cadastro de Nova Sala (`POST /salas`)

Nesta etapa, implementaremos o cadastro de novas salas no cinema.

```text
Postman (POST /salas) ➔ SalaController ➔ SalaService  ➔ SalaDAO ➔   Oracle
     (com JSON no            │              │             │          │  
      Request Body)     (Retorna 201     Chama o       (insert, gera ID
                          CREATED)     cadastrar           no banco)
```

### 3.1 Camada Service
A camada Service deverá validar os dados.
- **Regra 1:**
    - Nome obrigatório, não pode ser null ou vazio
    - Caso a regra seja violada, deverá lançar uma exceção IllegalArgumentException com a mensagem:
      O nome da sala é obrigatório.
- **Regra 2:**
    - Preço deve ser maio que zero
    - Caso a regra seja violada, deverá lançar uma exceção IllegalArgumentException
- **Regra 3:**
    - Uma sala sendo cadastrada não deve possuir uma data de exclusão.
### 3.2 Camada Controller
Na classe `Controller`, adicione o endpoint de criação:
- **Anotação:** `@PostMapping`
- **Lógica:**
    - Retorne a resposta com o código de status HTTP **201 Created**
